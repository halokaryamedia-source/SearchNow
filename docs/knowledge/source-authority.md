# Source Authority

Use this note only when evidence/state precedence is unclear.

## Authority chain

```text
current explicit user instruction
→ approved SearchNow decision
→ current SearchNow product/foundation requirement
→ recovered legacy evidence when legacy behavior is the question
→ current implementation source
→ tests / CI / runtime observations / generated artifacts as evidence
```

Authority decreases downstream for product meaning.

## Legacy evidence classes

The recovered BlueCoin documentation may establish:

- observed legacy binary/runtime facts;
- reconstructed internal relationships with stated confidence;
- historical behavior that SearchNow may choose to preserve or replace.

It may **not** establish that SearchNow must reproduce unsafe, hidden, or undesired behavior.

## Material user instructions

A material user instruction is authoritative even when it arrives only in chat. Persist it into the correct foundation/decision/continuation owner when it must survive future sessions.

Do not create one decision file per sentence or duplicate the same fact across many owners.

## Conflict rule

If material authorities conflict and precedence does not resolve them safely:

```text
UNKNOWN
→ identify both claims
→ identify affected owner/output
→ reconcile through the correct current owner
```

Never silently choose because one artifact looks newer or more polished.
